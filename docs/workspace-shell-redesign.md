# GGD Recorder 工作台式 UI 重构方案

## 目标

把当前“顶部六个标签页 + 页面之间切换”的传统交互，升级为围绕任务和对象工作的桌面工作台。核心体验是：用户始终知道自己正在处理什么、可以继续上一步工作，并且录制、录像、地图标注、截图和战绩分析可以连续协作。

本方案先改造应用壳层（Shell）和导航模型，再逐步迁移现有功能。第一阶段不改变录制、地图、截图和战绩的数据协议，降低重构风险。

## 设计原则

- **任务优先**：导航描述“我要做什么”，而不是暴露组件或页面名称。
- **上下文连续**：进入详情、复盘或标注时保留来源和返回路径，不重置用户状态。
- **全局状态可见**：录制状态、错误和待处理任务不依赖当前所在工作区。
- **就地操作**：选中对象后在右侧属性面板编辑；删除、复制、导出等动作统一到对象菜单。
- **渐进迁移**：先建立新的壳层和状态模型，现有 Tab 组件作为工作区内容复用，避免一次性重写六个功能。
- **键盘可达**：所有主要动作都有快捷键、焦点样式和命令搜索入口。

## 信息架构

```text
应用 Shell
├── 左侧导航 Rail
│   ├── 工作台
│   ├── 录制
│   ├── 录像库
│   ├── 标注工作区（地图 / 截图）
│   └── 战绩分析
│   └── 设置（底部低频入口）
├── 顶部 Context Bar
│   ├── 面包屑 / 返回
│   ├── 当前对象标题
│   └── 对象操作
├── 主工作区 Canvas
├── 可选右侧 Inspector
├── 全局录制 Dock
└── Command Palette（Ctrl/Cmd + K）
```

### 工作区职责

| 工作区 | 默认内容 | 高频动作 |
| --- | --- | --- |
| 工作台 | 最近录像、最近对局、最近标注、继续上次工作 | 开始录制、打开最近对象 |
| 录制 | 游戏进程、录制质量、开始/暂停/结束 | 开始录制、切换目标 |
| 录像库 | 录像列表、筛选、收藏、复盘入口 | 播放、标记、导出、删除 |
| 标注工作区 | 地图画布、截图画布、图层和对象面板 | 创建标记、连线、设置身份、导出 |
| 战绩分析 | 账号状态、对局列表、单局详情、玩家数据 | 查询、打开对局、定位玩家 |
| 设置 | 路径、质量、账号和应用偏好 | 修改配置 |

地图和截图在导航层合并为一个工作区，但保留两个画布模式；共享选择、图层、撤销/重做和右侧 Inspector。

## 页面壳层

### 左侧导航 Rail

- 桌面端宽度 232px，可收缩为 64px 图标栏。
- 导航项显示图标、短标题和必要的数量徽标（录像数量等）。
- 当前项使用窄色条 + 低对比背景，不使用大面积胶囊按钮。
- 设置固定在底部；录制中时导航顶部显示小型录制状态点。
- 移动/窄窗口自动切换为可展开的侧边抽屉，不恢复顶部六 Tab。

### 顶部 Context Bar

顶部只负责当前上下文，不承担主导航：

```text
录像库 / 2026-09-04 / 对局详情                         播放  标记  导出  ⋯
```

- 列表页显示工作区标题和筛选条件。
- 详情页显示返回按钮、对象名称和对象级操作。
- 标注页显示当前地图/截图、撤销重做和导出。
- 加载状态保留上下文标题，避免旧页面闪现。

### 全局录制 Dock

录制开始后固定在主窗口底部，跨工作区保持可见：

```text
● 正在录制   00:12:43   Goose Goose Duck                 暂停   结束录制   打开录像库
```

- 录制中可切换工作区、查看历史录像和做标注。
- 结束录制后 Dock 转为“正在保存 / 已保存 / 保存失败”三态，并提供重试或打开目录。
- Dock 不遮挡详情滚动区域，主工作区预留底部安全区。

## 导航与状态模型

新增壳层状态，不立即删除现有 `activeTab`：

```ts
type WorkspaceId = 'home' | 'record' | 'library' | 'annotate' | 'stats' | 'settings';

type NavigationEntry = {
  workspace: WorkspaceId;
  mode?: 'list' | 'detail' | 'review' | 'map' | 'screenshot';
  entityId?: string;
  title?: string;
};
```

- `navigationStack` 负责返回路径。
- `activeWorkspace` 负责主导航高亮。
- 旧的 `activeTab` 在迁移期间作为兼容映射，避免一次性改动所有子组件。
- 浏览器刷新或应用重启时，只恢复安全的列表工作区，不自动恢复正在编辑的临时对象。

## 交互约定

### 对象级操作

- 录像、对局、玩家、地图标记、连线都视为可选中的对象。
- 单击选中并打开 Inspector；双击进入详情或复盘。
- 右键打开统一上下文菜单；`Delete` 删除；`Esc` 清除选择或返回上一级。
- Inspector 采用固定宽度 320px，可收起；窄窗口改为底部抽屉。

### 命令面板

`Ctrl/Cmd + K` 打开全局命令面板，支持模糊搜索和最近命令：

- 开始录制 / 暂停录制 / 结束录制
- 打开录像库 / 打开地图 / 打开截图标注
- 查询我的战绩 / 打开最近对局
- 创建玩家标记 / 创建连线
- 导出当前标注 / 打开设置

命令项必须复用已有动作函数，避免命令面板产生第二套业务逻辑。

### 快捷键

| 快捷键 | 动作 |
| --- | --- |
| `Ctrl/Cmd + K` | 打开命令面板 |
| `Ctrl/Cmd + 1..5` | 切换主要工作区 |
| `Space` | 播放/暂停当前录像 |
| `Delete` | 删除当前选中对象 |
| `Esc` | 关闭面板、清除选择或返回 |
| `Ctrl/Cmd + Z` | 撤销标注操作 |
| `Ctrl/Cmd + Shift + Z` | 重做标注操作 |

## 分阶段实施

### Phase 0：基线与保护

- 保留当前 `codex/ui-modern-clean` 已合并到主分支的功能。
- 为导航、录制 Dock、返回栈和 Inspector 建立组件级测试。
- 记录当前六个入口的行为和快捷键，确保迁移后动作不丢失。

### Phase 1：Shell 外壳

- 新增 `AppShell`、`WorkspaceRail`、`ContextBar`、`RecordingDock`。
- 用工作区映射替代顶部六 Tab 的视觉呈现。
- 暂时复用现有 `GameTab`、`RecordingsTab`、`MapTab`、`ScreenshotTab`、`StatsTab`、`SettingsTab`。
- 保持 URL、IPC、数据结构不变。

### Phase 2：导航栈与详情模式

- 把录像详情、战绩单局详情、地图/截图编辑纳入 `NavigationEntry`。
- 统一返回行为和上下文栏动作。
- 保留当前对局详情全屏能力，并让它成为通用详情布局。

### Phase 3：标注工作区统一

- 地图与截图共享选择、图层、右键菜单、撤销/重做和 Inspector。
- 迁移玩家身份、连线和截图框选交互。

### Phase 4：命令面板与快捷键

- 建立命令注册表，接入所有高频动作。
- 增加键盘导航、焦点管理和无障碍标签。

### Phase 5：清理旧结构

- 删除顶部 Tab 样式和旧的页面跳转兼容代码。
- 收敛重复 CSS 和重复状态。
- 对关键流程做真实窗口回归测试。

## 成功标准

- 用户无需返回“录制”工作区即可暂停或结束录制。
- 从录像进入复盘、从战绩进入单局详情时，返回一次即可回到原列表和原筛选状态。
- 地图和截图中的对象都支持一致的选中、右键、删除和 Inspector 编辑。
- 六个原功能入口仍然可达，但不再以顶部六个平级 Tab 呈现。
- 1200px 桌面窗口和窄窗口均无横向溢出；键盘操作有可见焦点。
- 现有测试全部通过，并新增壳层、导航栈和录制 Dock 的交互测试。

## 第一阶段不做的事

- 不重写录制编码、IPC 或 Gaggle API。
- 不在没有对象模型和撤销策略前，把地图和截图强行合并成一份数据。
- 不引入需要联网的设计系统或运行时依赖。
- 不用动画掩盖状态迁移问题；动效仅用于导航层级和状态反馈。
